# 前端交互流程 V1

日期：2026-09-28，Asia/Shanghai  
状态：`FROZEN_INTERACTION_V1`

上位规范：

1. `FRONTEND_STORY_CHAIN.md` 最终冻结版；
2. `FRONTEND_DATA_MAPPING.md`。

本文冻结用户如何沿证据链浏览和操作，不修改后台接口、现场模型或权限。

## 1. 全局交互原则

1. 所有页面先回答当前处于哪个 `Simulation / Run / Role`；
2. 业务浏览优先使用 `sim_time`，墙钟时间作为事件产生、接收和诊断辅助；
3. 地图、列表、时间轴和详情使用同一选中对象；
4. 页面只展示真实证据、确定性计算和明确标注的操作者声明；
5. 缺失数据进入 `UNKNOWN / PARTIAL / INSUFFICIENT`，不使用演示默认值；
6. stale 实体保留最后位置用于定位，但速度和实时状态降级；
7. 只有 `EXECUTED` 使用“已执行”；
8. 所有改变现场或业务状态的操作必须二次确认并展示最终结果；
9. 历史回放完全只读，不能触发推理、派单或告警流转；
10. 浏览器刷新后尽量从 URL 恢复当前 Run、页面、对象和时间点。

### 1.1 决策术语

前端展示术语统一为：

| 页面术语 | 含义 | 当前 API 兼容值 |
|---|---|---|
| `DISPATCH` / 调度决策 | 选择目标铲装点的任务调度决策 | `TASK` |
| `CONTROL` / 协同控制决策 | 速度控制参考或加速度决策 | `SPEED` |

页面不得把二者表述为两个任务系统。请求现有接口时可以继续使用 `TASK/SPEED` 枚举，但组件标题、筛选标签和用户文案统一使用 `DISPATCH/CONTROL`。


## 2. 角色入口与路由

### 2.1 登录分流

```text
/login.html
  ├── DISPATCHER → /
  ├── VEHICLE    → /vehicle.html
  └── SHOVEL     → /shovel.html
```

若用户访问无权限页面：

- 调度员回到 `/`；
- 车辆回到 `/vehicle.html`；
- 铲端回到 `/shovel.html`；
- 未登录跳转登录页，并通过 `next` 保存原目标。

### 2.2 调度中心页面状态

V1 调度中心允许先以单页页签实现，不要求新增后端路由：

```text
/?view=overview&simulationId=SIM_001&runId={runId}
/?view=monitor&simulationId=SIM_001&runId={runId}&vehicleId={id}
/?view=decision&runId={runId}&decisionId={id}
/?view=cycle&runId={runId}&cycleId={id}
/?view=replay&runId={runId}&simTime={seconds}&queryWallTime={millis}
```

URL 参数是可恢复的前端状态，不改变现有 API。`simTime` 是用户看到和操作的主时间；`queryWallTime` 是当前回放 API 所需的辅助查询参数。

## 3. 全局框架

调度中心固定区域：

```text
顶部栏
├── 产品身份
├── Simulation
├── 当前 Run / 场景
├── 仿真业务时间
├── MQTT 状态
├── 现场在线状态
└── 当前用户

主导航
├── 运行总览
├── 实时监控
├── 决策证据
├── 周期故事
└── 历史回放
```

MQTT 已连接与现场在线必须是两个独立状态，不能合并成一个绿点。

## 4. 首次加载状态机

```text
读取身份
  ↓
读取 Simulation 列表
  ↓
确定 simulationId
  ↓
读取 Run 列表
  ↓
优先选择活动 Run；无活动 Run 则选择最近历史 Run
  ↓
并行读取 Snapshot / Health / Alerts / Production Summary
  ↓
连接 WebSocket
```

状态定义：

| 状态 | 页面行为 |
|---|---|
| `LOADING` | 显示骨架和正在读取的对象，不展示 0 值 |
| `READY_LIVE` | 活动 Run + WebSocket 正常 + 现场在线 |
| `READY_STALE` | 数据存在但现场 stale；显示最后状态时间 |
| `READY_HISTORY` | 选择已结束 Run；进入只读历史语境 |
| `EMPTY` | 没有 Run 或没有状态证据；提供明确说明 |
| `ERROR` | 显示失败接口、HTTP 状态和重试入口 |

## 5. 调度员主验收流程

固定演示路径：

```text
选择 Run
  → 查看运行概况
  → 进入实时监控
  → 选择车辆
  → 打开调度决策证据
  → 检查 Command 与 Ack
  → 查看人工干预
  → 打开 Cycle
  → 查看生产结果
  → 历史回放复查
```

每一步必须保留上一步上下文，返回时不丢失 Run、车辆和时间位置。

## 6. Run 选择流程

### 6.1 选择

1. 打开 Run 选择器；
2. 按开始时间倒序展示运行；
3. 每项显示场景、开始/结束、状态和数据质量；
4. 选择后更新 URL `runId`；
5. 清空与旧 Run 绑定的 decisionId、cycleId 和回放时间；
6. 重新读取运行上下文、事件、生产摘要和可用周期。

### 6.2 无活动 Run

页面显示：

> 当前没有正在进行的运行。正在查看最近一次历史运行。

不得把最新 Snapshot 自动归入历史 Run；历史数据只由运行边界和回放接口提供。

## 7. 运行总览流程

### 7.1 默认信息顺序

```text
运行身份与数据质量
  → 链路/现场健康
  → 车辆和铲装点概况
  → 作业阶段周期与产量
  → 活动告警
  → 最近关键事件
```

### 7.2 卡片点击

| 卡片 | 点击结果 |
|---|---|
| 在线车辆 | 进入实时监控并应用“在线”过滤 |
| stale 车辆 | 进入实时监控并应用“失联”过滤 |
| 活动告警 | 打开告警列表，定位对象 |
| 作业阶段周期 | 进入周期故事列表 |
| 决策/指令异常 | 进入决策证据并过滤失败状态 |

统计卡片必须显示口径提示；当前 `completeCycles` 使用“作业阶段完整周期”。

## 8. 实时监控流程

### 8.1 选择车辆

入口：地图车辆标记、车辆列表、告警对象、全局搜索。

选择后：

1. 地图标记高亮并居中；
2. 车辆列表同步选中；
3. 打开车辆详情抽屉；
4. URL 写入 `vehicleId`；
5. 加载最近 DISPATCH/CONTROL 决策和人工改派记录；
6. 若存在显式 cycleId，显示周期入口。

### 8.2 车辆详情动作

| 动作 | 结果 |
|---|---|
| 查看决策证据 | 打开最近相关决策，保留 vehicleId |
| 查看指令历史 | 按 vehicleId 查询运行事件/决策 |
| 查看周期 | 只在存在源端 cycleId 时进入 |
| 人工改派 | 进入第 10 节确认流程 |
| 关闭详情 | 清除 URL vehicleId，保留地图视角和筛选 |

### 8.3 stale 车辆

选择 stale 车辆仍可查看最后位置和历史证据，但详情头部必须显示：

```text
状态失联 · 最后接收于 {time} · 数据年龄 {age}
```

速度显示 `--`，状态显示“过期”，人工改派按钮禁用并说明原因。

### 8.4 选择铲装点

选择后同步地图和铲装点列表，详情展示可用性、作业状态、等待数量、服务数量、目的地匹配来车和相关决策。

当前不能展示具体服务/排队车辆名单；来车只能标注“目的地匹配”，不能标注 ETA。

## 9. 决策证据流程

### 9.1 列表

筛选项：Run、车辆、铲装点、`DISPATCH/CONTROL`、来源、校验状态、Ack 状态。

列表行只显示：业务对象、触发、决策类型、输出摘要、Command 状态、业务时间/墙钟时间。

### 9.2 详情

点击后按固定顺序展开：

```text
决策身份
  → 触发事件
  → 车辆网关状态
  → 候选状态
  → 决策输入快照（如调度模型 27 维输入）
  → 模型原始输出
  → 后台校验
  → Command 发送
  → Ack
  → 关联周期（若有显式引用）
```

折叠策略：默认展开输出、校验和 Ack；决策输入快照和原始 JSON 默认折叠。27 维结构只适用于当前调度决策输入，不要求 CONTROL 决策具有相同维度。

### 9.3 状态表达

- `PASSED`：已校验，不等于已执行；
- `SENT/PENDING`：等待现场结果；
- `EXECUTED`：现场已执行；
- `REJECTED/PUBLISH_FAILED/EXPIRED`：置顶展示原因；
- 无 explanation：显示“模型未提供因果解释”，不隐藏该事实。

## 10. 人工改派流程

人工改派是有业务影响的操作，交互固定为三阶段。

### 10.1 准备

1. 从选中车辆进入；
2. 显示车辆、载荷状态、当前节点、原目标和当前数据年龄；
3. 现行已验收前端按既有固定集合展示装载目标或卸载目标；
4. stale、无目标或已有待处理指令时禁用提交。

人工改派业务链路已经存在并通过既有验收，不属于实现缺口。当前没有独立的“可选改派目标集合”查询接口，
因此前端目标集合仅用于操作选择，不代表授权或业务校验结果。提交后的合法性始终以
`ManualDispatchService` 对车辆在线、行驶态、载荷兼容、目标存在和路线可达的校验为准。

已验证链路：`前端二次确认 → POST manual-dispatch → MQTT Command → AnyLogic 安全节点换路 → EXECUTED / REJECTED Ack → ManualDispatchCommand / DecisionTrace / Audit`。

### 10.2 确认

确认对话框必须展示：

```text
车辆：T{id}
原目标：{previousDestinationNode}
新目标：{targetNode}
影响：将在安全节点应用新路线，最终状态以现场 Ack 为准
```

按钮：`取消`、`确认下发`。不能使用模糊的“确定”。

### 10.3 结果

提交成功只显示“已发送/等待执行”，不乐观显示“改派成功”。

```text
SENT/PENDING → 等待回执
EXECUTED     → 已执行
REJECTED     → 已拒绝 + 原因
PUBLISH_FAILED → 下发失败 + 原因
```

收到最终状态后刷新人工改派历史、决策证据和周期指令引用。周期事件尚未变化时，不声称后续作业已经切换。

## 11. 周期故事流程

### 11.1 周期列表

按车辆、数据质量和时间筛选。每项显示：cycleId、车辆、当前已收事件数、作业阶段状态、指令关联状态和产量结果。

### 11.2 周期详情

```text
周期身份/数据质量
  → 冻结版完整循环缺口提示
  → 任务指令沿革
  → 决策证据摘要
  → 生产事件时间轴
  → 吨数/品位/阶段时长
  → 原始证据入口
```

当前事件按 `simTimeSeconds` 排序。同一 sim time 使用业务语义顺序，不按 eventId 排序。

### 11.3 完整性表达

冻结版完整 Cycle 的业务边界为：

```text
UNLOAD_FINISHED(previous)
  → DISPATCH_TRIGGERED
  → HAUL_EMPTY_START
  → ARRIVE_SHOVEL
  → LOAD_START
  → LOAD_FINISHED
  → HAUL_FULL_START
  → ARRIVE_DUMP
  → UNLOAD_START
  → UNLOAD_FINISHED(current)
```

末尾的 `UNLOAD_FINISHED(current)` 是运输完成和产量确认的闭合事件。当前已有八事件继续用于“作业阶段完整”判断；冻结版完整运输循环缺少任一关键事件时不得强行判为完整。

- 当前八事件齐全：显示“作业阶段完整”；
- 冻结版卸载到卸载事件仍缺失：完整运输循环 `INSUFFICIENT`；
- 少于当前八事件：显示“作业阶段未完成”；
- 时间倒序：显示“事件顺序异常”，不计入统计；
- 指令引用无法解析：显示 `PARTIALLY_RESOLVED/UNKNOWN`。

## 12. 历史回放流程

### 12.1 进入

只能从已选择 Run 进入。默认时间：历史 Run 的结束前最后可用时刻；活动 Run 默认当前接收墙钟时间。

### 12.2 查询

1. 用户移动墙钟时间选择器；
2. 页面调用 `/replay?atWallTimeMs=`；
3. 地图展示该时刻之前已持久化的最新样本；
4. 主标题展示样本的 `sim_time`；
5. 辅助标签展示查询墙钟和样本接收时间；
6. 同步定位事件时间轴附近记录。

### 12.3 回放限制

固定显示：

> 基于持久化样本重建，不插值；当前按接收墙钟时间查询。

回放模式下隐藏或禁用人工改派、告警流转和终端操作。

## 13. 告警与审计流程

告警状态：`OPEN → ACKNOWLEDGED → PROCESSING → CLOSED`。

每次流转前显示对象、告警信息、当前状态和下一状态。关闭告警必须填写处理结果。

告警列表操作完成后：

1. 刷新告警；
2. 刷新审计；
3. 保留筛选和滚动位置；
4. 显示成功或失败反馈。

审计记录只读，不提供修改或删除入口。

## 14. 车端 HMI 流程

```text
认证绑定车辆
  → 读取本车快照
  → 查看任务指令和下一目标
  → 查看执行/Ack
  → 查看最新控制参考
  → 查看告警
  → 确认任务或上报异常
```

规则：

- 实体选择器只显示绑定车辆且不可编辑；
- 当前无独立 Task，页面使用“任务指令”；
- 状态目标和决策目标不一致时并列展示；
- 提交终端操作后显示服务端受理结果，不假设现场状态改变；
- stale 时仍可上报异常，但“确认当前任务”应禁用。

## 15. 铲端 HMI 流程

```text
认证绑定铲装点
  → 查看可用/作业状态
  → 查看服务数量和等待数量
  → 查看目的地匹配来车
  → 查看相关任务指令
  → 确认任务或上报异常
```

规则：

- 实体选择器只显示绑定铲装点且不可编辑；
- 不展示未经采集的具体服务车辆和排队车辆名单；
- 来车不显示 ETA，只显示车辆、当前位置/路段和速度；
- stale 时所有实时数量显示 `--`，仍可上报异常。

## 16. 通用反馈

### 16.1 空状态

空状态必须说明“为什么为空”和“如何获得数据”，例如：

- 未开始 Run；
- 尚未收到 MapState；
- 当前筛选无决策；
- 周期尚未完成；
- 字段未采集。

### 16.2 错误

错误反馈包含：操作、HTTP 状态、服务端 message、重试入口。不得只写“失败”。

### 16.3 加载

首次加载使用骨架；局部刷新保留旧内容并显示“更新中”，防止界面跳空。

### 16.4 成功

成功反馈说明实际达到的阶段，例如“请求已受理”“指令已发送”“现场已执行”，不得统一写“成功”。

## 17. 键盘与可访问性

- 地图标记必须有对应可键盘访问的车辆/铲列表；
- 页签、详情、对话框和时间轴具有明确焦点顺序；
- 对话框打开后聚焦标题或第一个控件，关闭后返回触发按钮；
- 状态变化通过 `aria-live` 播报；
- 颜色之外始终提供文字和图标；
- 支持 `prefers-reduced-motion`；
- 表单错误与具体字段关联。

## 18. 响应式规则

### ≥ 1440 px

地图与详情并列，运行总览可同时展示关键指标和事件。

### 1024–1439 px

地图保持主体，详情使用可收起侧栏，次要指标折叠。

### < 1024 px

调度中心进入只读摘要优先布局；地图、列表和详情纵向排列。高风险调度操作仍可用，但必须完整显示确认内容。

车端/铲端优先适配平板，不依赖横向大屏。

## 19. 交互验收清单

1. 登录后按角色进入正确终端；
2. URL 可恢复 Run、页面和选中对象；
3. 无活动 Run 不会把最新状态错误归入历史运行；
4. 地图与实体列表选择同步；
5. stale 状态按规范降级且禁用不安全操作；
6. 决策详情能顺序查看输入、输出、校验、Command 和 Ack；
7. 人工改派在确认前展示对象、原目标、新目标和影响；
8. 指令发送后不提前显示已执行；
9. 周期详情区分作业阶段完整与冻结版完整运输循环；
10. 回放明确只读、不插值且双时间显示；
11. 所有空状态和错误状态可解释；
12. 键盘可以完成主要浏览流程；
13. 车端和铲端不能越权浏览全局数据；
14. 页面刷新后不会丢失关键上下文；
15. 所有业务结论都可回到原始证据。

完成本交互冻结后，下一阶段可以进行页面线框和视觉系统设计。
